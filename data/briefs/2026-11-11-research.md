# Research Pass: Local-First Smart Homes & The Internet-Free Mandate
**Date (IST):** 2026-11-12  
**Topic/Slug:** local-first-smart-home-mandate  
**Primary Source:** Spencer Kittleson, *"Smart home devices should work without the internet"*, Do Code That Matters (docodethatmatters.com).  
**Hacker News Discussion:** 1,105 points, 362+ comments (posted Nov 10, 2026).

---

## 1. Core Story & Primary Source Details
*   **The Catalyst:** Developer Spencer Kittleson published a comprehensive essay detailing his 10-year journey of running a multi-user smart home under a strict "local-first" design philosophy. 
*   **The Core Thesis:** Smart homes must degrade gracefully. If the internet connection drops, the physical house must remain fully operational.
*   **Real-World Failures Cited (`CONFIRMED_PRIMARY`):**
    *   **Google Nest:** Kittleson's Nest integration broke overnight because Google changed/deprecated its API.
    *   **Samsung Fridge:** A smart refrigerator threw a blocking TLS certificate error on its own screen because it couldn't reach the cloud.
    *   **Camp Chef Grill:** A smart grill controller refused to display the meat temperature on its local screen unless it had an active Wi-Fi connection to the cloud.
    *   **Anova Meat Thermometer:** Stopped working entirely when the company shut down its servers, turning working hardware into e-waste.

---

## 2. The 11 Rules of Local-First Home Automation (`CONFIRMED_PRIMARY`)
Kittleson's decade of experience distilled into actionable rules:
1.  **No internet, no problem:** Core functions (lights, locks, garage) must work with the ethernet cable unplugged.
2.  **Don't remove the old way while adding the new one:** Never bypass physical controls. If a family member has to tape a wall switch "on" so a smart bulb keeps power, the design has failed.
3.  **Be agile:** Rooms change usage and residents move; the system must be cheap and easy to modify.
4.  **Check your automations:** Audit scheduled triggers periodically (e.g., finding four separate schedules firing the same garden pump).
5.  **Exceptions must be exceptional:** Only break rules for reasons you would still agree with six months later.
6.  **Cloud devices need an API with logs:** No black boxes allowed in the house.
7.  **Config lives in one place:** Avoid managing configurations across five different vendor apps.
8.  **More than one way in:** Provide multiple control paths (app, voice, physical QR codes, or NFC tags).
9.  **Routines over manual steps:** If you repeat the same steps daily, automate them into a single routine.
10. **Pub/Sub over Point-to-Point:** Devices should talk via MQTT so sensors publish state without caring who is listening (decoupling).
11. **No batteries under a 1-year lifespan:** Nobody wants to swap a door sensor battery at 2:00 AM.

## 3. Kittleson's Hardware & Software Stack (`CONFIRMED_PRIMARY`)
*   **Microcontrollers:** ESP8266 and ESP32 D1 Mini boards running **Tasmota** (open-source local firmware).
*   **MQTT Broker:** Runs locally on the home router—a **GL.iNet Flint 2** running **OpenWrt**.
*   **Logic Engine:** **Node-RED** running on a **Raspberry Pi 4**.
*   **Visualization & History:** **Grafana** running on the same Raspberry Pi 4.
*   **Remote Access:** **Tailscale** installed on the router to access the local network securely without exposing individual IoT devices to the internet.
*   **Voice Assistant:** Amazon Alexa (treated strictly as an *extra* convenience layer, never a critical dependency).
